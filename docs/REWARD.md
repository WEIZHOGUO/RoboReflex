# 机映 RoboReflex —— 自适应奖励函数设计（α 动态值）

> 2026-10-04 · 解决"固定 λ 两难"：惩罚太重策略躺平（宁可不接），太轻延迟形同虚设

## 一、问题

固定 λ 的奖励 `R = 成功 − λ·延迟` 存在死结：

- 训练早期：策略还不会接球，延迟惩罚雪上加霜 → 学会"缩头乌龟"（少动少错）
- 训练后期：接球已熟练，固定 λ 给的延迟压力恒定 → 无法持续压榨更快反应

## 二、设计：α 动态值（拉格朗日自适应惩罚）

**完整奖励函数**：

```
R = 1[接球成功] − α_t · (t_response / t_window)

t_response  = 刺激发生 → 首次有效动作 的延迟
t_window    = 刺激发生 → 球到达 的物理时间窗（归一化基准）
α_t         = 动态延迟惩罚系数（每个评测窗口更新）
```

**α 的更新规则**（对成功率做闭环控制，类拉格朗日对偶更新）：

```
α_{t+1} = clamp( α_t + η · (SR_recent − SR_target),  α_min, α_max )

SR_recent = 最近 N 次试验的接球成功率（滑动窗口）
SR_target = 目标成功率（如 0.85）
η         = 更新步长（如 0.02）
```

**直觉**：成功率高于目标 → 说明"接球"已掌握，加码延迟压力（α↑）；成功率跌破目标 → 惩罚压垮了基本盘，减压（α↓）。系统自动骑在"成功率和延迟的最优折中点"上——这正是约束强化学习（CMDP）的拉格朗日松弛形式：

```
最大化  成功率
约束    延迟 ≤ 预算
α_t 就是约束的拉格朗日乘子的在线估计
```

## 三、工程细节

1. **延迟项归一化**：除以 t_window（球飞行时间），保证惩罚项在 [0,1+] 区间，不同球速下量纲一致——球越快窗口越小，同样的延迟占比越大、扣得越多，天然实现"快球更苛刻"
2. **α 更新频率**：每个评测窗口（如每 1000 次试验）更新一次，不在单步内抖动
3. **超参初值**：α_min=0（冷启动不惩罚）, α_max=2.0, SR_target=0.85, η=0.02, 滑动窗 N=1000
4. **训练课程自然涌现**：α 从 0 起步 → 策略先学会接 → α 自动爬升 → 策略被迫提速——不需要手写课程表

## 四、与对照组的关系（消融矩阵升级）

| 组 | 奖励 | 目的 |
|---|---|---|
| A | 手写解析基线 | 传统预编程反射 |
| B | PPO，λ=0 | 消融：无延迟意识 |
| C | PPO，固定 λ（扫描 3 档） | 消融：固定惩罚的代价 |
| D | PPO，**α 动态值**（本方案） | 机映主张 |
| E | 无反射慢规划 | 反证 |

预期结果叙事：D 在"成功率-延迟"帕累托前沿上压过 B 和所有 C 档——因为 C 的每一档都是帕累托曲线上的一个固定点，而 D 自动收敛到最优点。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| α 震荡（成功率在目标附近抖动导致 α 来回跳） | η 小步长 + SR 滑动平均平滑；必要时 η 随训练衰减 |
| SR_target 设太高导致永远加压 | SR_target 选低于手写基线成功率的值，留出余量 |
| α 被奖励 hacking（策略用超小动作骗"首次动作"时间戳） | "首次有效动作"定义加位移/加速度阈值，纹丝不动不算响应 |
