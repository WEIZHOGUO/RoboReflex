# 机映 RoboReflex —— 平台架构设计 v0.1

> Windows 原生 · 反射作为一等训练对象 · 开源（GitHub 待发）· 论文配套
> 2026-10-04 初稿

## 一、一句话定义

机映 = **刺激场景生成 × 延迟约束训练 × 毫秒级延迟测量** 的闭环平台，让 AI/机器人策略把"反射"当作可训练、可测量、可复现的技能来学。

## 二、MVP 场景：接球（Ball Catch）

选型理由：Delbruck RoboGoalie 先例（Windows 2ms 反应）、刺激直观（球飞来）、成功/失败判定无歧义、延迟曲线天然可画。

- 仿真：MuJoCo（pip 直装，Windows 原生）
- 机体：平面挡板（paddle，1 自由度横移）——比机械臂更聚焦"反射"本身，机械臂留作二期
- 刺激：随机初速/角度/抛物线发球机，分布可配
- 观察：球+挡板状态（位置/速度），观测→动作链路全程打时间戳

## 三、模块架构

```
src/
├── stimuli/    刺激注入引擎：发球分布、事件调度、难度曲线（课程学习）
├── reflex/     反射策略：Gymnasium 环境封装 + PPO 训练（stable-baselines3）
├── latency/    延迟测量：事件→首次动作 时间戳、分位数剖面（p50/p95/p99）
├── bench/      评估基准：成功率、延迟直方图、vs 手写规则基线对比
├── scenarios/  场景配置（YAML）：新场景=新配置，不写代码
└── assets/     模型 XML、示意图
```

数据流：`场景配置 → 刺激注入 → [环境步进 + 全程时间戳] → 策略动作 → 延迟剖面+成功率 → 训练反馈`

## 四、核心差异化设计（论文卖点）

1. **延迟感知奖励**：reward = 接球成功 − λ·反应延迟——把"快"写进目标函数，不是事后统计
2. **延迟剖面测量**：每一次试验记录 事件时刻/首动时刻/完成时刻，输出 p50/p95/p99 直方图——别人报成功率，我们报延迟分布
3. **双通路硬解耦**：慢速规划通路（低频、深思熟虑）+ 快速反射通路（高频、被训练对象）+ 仲裁器（危险判定，决定反射是否接管）。反射层与主策略**禁止共享权重**——这是与"大网络里混应激逻辑"的物理隔离
4. **误触发率指标**：反射在无威胁时乱动=误报，评估体系记录触发精确率/误报率，与延迟剖面并列
5. **场景即配置**：YAML 定义刺激分布，论文复现实验=贴配置文件
6. **基线对照内置**：手写预测拦截规则 vs 训练策略 vs 无反射（慢速规划），三组对比直接出论文图

## 四·三、对抗性评审后的架构加固（2026-10-04 v0.2）

针对路人/评委挑出的 13 条缺点，以下五条**现在修**：

1. **仲裁器加防震荡设计**：滞回比较器（进入阈值 > 退出阈值）+ 最短驻留时间（dwell time），杜绝乒乓切换；切回慢通路前做**状态交接**（把当前观测回放给慢通路做状态重同步），解决"切得过去、切不回来"的控制跳变
2. **仿真时间 vs 墙钟时间双轨测量**：延迟剖面同时报逻辑时间（可复现）和墙钟时间（真实感），论文里明确区分，不给"仿真时间不算数"留攻击面
3. **评测/部署双模式**：Profiler 只在评测模式挂载，部署模式零开销；导出包=快通路 ONNX + 仲裁器独立小模块（纯配置+参考实现，几十行，可移植）
4. **失败案例采集器**：bench 模块自动归档失效场景（什么条件下误触发暴增/仲裁失效），论文"失败案例分析"小节的素材库
5. **第二场景进路线图**：避障场景（移动体）作为 M4 的通用性证据——场景即配置的设计让新增场景只写 YAML 不碰代码

明确列为**未来工作**（论文局限性章节坦然承认）：可学习的仲裁触发条件（替代手写阈值）、真机 sim-to-real 验证、真实世界危险事件回放。

## 五、技术栈与平台策略（2026-10-04 修订：双平台）

Python 3.11+ + MuJoCo + Gymnasium + stable-baselines3（PPO）+ PyYAML + matplotlib + ONNX（策略导出）。
全 pip 安装、无 ROS 依赖。

**双平台定位（用户拍板）**：

- **Windows**：差异化主场——个人开发者/学生/科创场景，pip 直装即用，训练+测量全功能
- **Linux**：科研主流盘——同一套代码直接跑（MuJoCo/SB3 跨平台原生），额外吃到 fork 模式多进程采样提速、将来兼容 Isaac Lab/ROS 生态
- 平台相关代码只收进一个 `platform_compat` 层（时间戳源、进程启动方式 spawn/fork、渲染后端），其余代码零分支
- CI 矩阵（开源后）：GitHub Actions 双平台跑测试——README 上双平台 badge 是说服力的一部分

## 八、答辩 FAQ（2026-10-04 路人八问）

1. **裁判延迟瓶颈**：仲裁器=微秒级几何阈值判定，全系统最便宜的计算；AI 只在离线慢环优化其参数，不进实时路径。裁判/反射延迟分开记账。
2. **指令冲突**：排他 mux 切换不混合，同一时刻只有一条通路到电机；切换瞬时 20ms 插值过渡窗。
3. **误判抽搐**：滞回+驻留时间（机制层）+ 无威胁期反射输出幅值惩罚（奖励层）双保险。
4. **换硬件**：不承诺零微调。技能模板+适配层+域随机化训练，换机=重写适配器+少量微调。
5. **异构接口**：策略在任务空间（语义速度指令）训练，非关节空间；各机型 IK 自译。
6. **AI 作弊**：考场/奖励/物理参数全在平台侧，考生只读观测；未来 AI 生成场景也双系统分离+参数只读签名。
7. **信用分配**：短 episode + 延迟密集信号 + GAE 回溯 + 终局截断。
8. **Windows→真机实时性**：Windows 只产策略（ONNX 数据文件），实时环在部署侧 Linux/PREEMPT_RT；ONNX 小 MLP 推理几十微秒。

## 九、红队第二轮（边界与极端情况攻防，2026-10-04）

1. **感知盲区/旋转球**：裁判用保守包络+TTC 判定（微秒级，无需精确轨迹）；KF 几十微秒级；Profiler 账本升级为五段式（传感/感知/裁判/推理/执行）。
2. **过渡窗致命**：非对称握手——切入反射硬切（0ms），交还慢通路软过渡；window=min(20ms, k·TTC)；力矩尖峰由驱动层电流限幅兜底。
3. **装死陷阱**：误触发惩罚打在仲裁器（乱拉警报者）而非反射策略身上；不等式 C_miss > C_false_trigger 保证威胁窗口内静止=必然净亏。
4. **IK 不可达**：投影到最近可行域+裁剪反馈回传+训练期带镣铐（限幅进训练环），绝不静默失败。
5. **感官欺骗免疫**：奖励只从仿真物理真值计算，不从传感器读数计算；骗传感器=骗自己；观测噪声随机化防模式作弊。
6. **ONNX 内存抖动**：部署套件提供静态内存纯 C 前向实现（零分配零系统调用），ONNX 便捷/C 决战双格式；MCU 走 CMSIS-NN。
7. **多物体**：裁判是 O(N)（物体×保护区，min-TTC 优先），非 O(N²)；空间哈希兜底大场景。
